# Story 3.6 : Placement intelligent — interleaving taille/famille

## Status

Ready for Review

---

## Story

**As a** ingénieur électricien utilisant TontonKAD,
**I want** que le moteur de placement insère automatiquement les petits fourreaux dans les espaces laissés entre les grands, au lieu de les placer en bloc après,
**so that** la boîte résultante soit plus compacte, que l'occupation soit maximisée, et que le placement reflète la logique métier (les petits CFA peuvent s'insérer entre les gros CFO sans enfreindre la ségrégation de niveaux).

---

## Acceptance Criteria

1. Après un `⚡ PLACEMENT AUTO`, les petits fourreaux (diamètre < 50 % du plus grand du même niveau ou du niveau adjacent) sont essayés **en remplissage** dans les espaces disponibles entre les grands déjà placés, avant d'ouvrir une nouvelle rangée.
2. La contrainte de **ségrégation de niveaux** est respectée : un fourreau CFA (niveau haut) ne peut pas être inséré dans une rangée CFO (niveau bas), même si l'espace le permettrait géométriquement.
3. La **surface totale** de la boîte résultante est inférieure ou égale à ce que produisait l'ancienne stratégie `familyLevelStrategy` sur les mêmes données (régression de surface interdite).
4. Le **score global** (`NappeScorer`) de la configuration interleaved est ≥ au score de la configuration purement séquentielle sur un jeu de test représentatif (3 familles, 3 tailles).
5. La nouvelle stratégie est exposée comme `interleavedStrategy` dans `NappeGenerator` et enregistrée dans la liste des stratégies du mode `auto`.
6. Si `interleavedStrategy` retourne `null` (cas impossible — contrainte largeur trop petite), le moteur tombe en fallback sur `familyLevelStrategy` sans erreur.
7. `buildNappeVariants()` dans `script.js` continue à afficher correctement les variantes issues de la nouvelle stratégie dans le panel (SVG preview + label).
8. Tous les tests Jest existants passent (≥ 129). Au moins **5 nouveaux tests** couvrent `interleavedStrategy` :
   - Interleave réel détecté (petit inséré entre deux grands)
   - Ségrégation de niveaux respectée (CFA non inséré dans rangée CFO)
   - Surface ≤ `familyLevelStrategy` sur même entrée
   - Fallback sur `familyLevelStrategy` si contrainte trop stricte
   - Performance < 100 ms sur 30 fourreaux mixtes

## Dev Notes

### Problème racine

L'algorithme actuel (`familyLevelStrategy`) place les fourreaux **séquentiellement dans l'ordre de tri** : d'abord tous les grands, puis tous les moyens, puis tous les petits. Le résultat est une configuration en "blocs de taille" qui laisse des espaces rectangulaires inutilisés dans les rangées des grands, que les petits auraient pu occuper.

**Exemple concret** :
```
Avant (familyLevel) :        Après (interleaved) :
┌─────────────────────┐      ┌─────────────────────┐
│ [200][200]          │      │ [200][63][200][63]  │
│ [125][125][125]     │      │ [125][63][125][63]  │
│ [63][63][63][63]    │      │ (2 rangées au lieu de 3)
└─────────────────────┘      └─────────────────────┘
```

### Contrainte de ségrégation (invariant métier à RESPECTER)

La règle de niveaux (`niveauxParFamille`) sépare :
- **Bas** : CFO_PUISSANCE, IRVE, RESERVE_CFO
- **Médian** : CFO_SECONDAIRE, ECLAIRAGE, RESERVE
- **Haut** : CFA_SURETE, VDI, FIBRE, GTB, RESERVE_CFA

Un fourreau CFA **ne doit jamais** être dans la même rangée qu'un fourreau CFO. L'interleaving ne mélange que **des fourreaux du même niveau**.

### Algorithme `_findGapsInRow` — pseudocode

```
_findGapsInRow(config, targetY, rowHeight, csCandidat):
  // Positions occupées dans cette rangée
  occupés = [pf for pf in config.placedFourreaux if pf.y === targetY]
  // Trier par x croissant
  occupés.sort(key=x)
  
  gaps = []
  cursor = m  // litDePose gauche
  for pf in occupés:
    pfCs = calculateCellSize(pf.diameter)
    if pf.x > cursor + csCandidat:  // espace entre cursor et pf.x
      gaps.push({ x: cursor, width: pf.x - cursor })
    cursor = pf.x + pfCs
  // Espace après le dernier fourreau
  if config.width - m - cursor >= csCandidat:
    gaps.push({ x: cursor, width: config.width - m - cursor })
  
  return gaps.filter(g => g.width >= csCandidat)
```

### Structure des rangées dans `NappeLayout`

`config.placedFourreaux` est un tableau `[{ id, diameter, x, y }]`.
- `x`, `y` = coin **bas-gauche** de la cellule (Y=0 en BAS dans le moteur)
- `calculateCellSize(diameter)` = diameter + PLACEMENT_RULES.entraxe (30mm)
- Pour identifier les rangées : grouper par `y`
- Pour un fourreau de niveau `n`, ses rangées ont `y` parmi les valeurs uniques de `placedFourreaux` filtrés par même niveau

### Mapping niveau → fourreaux déjà placés

Pour `interleavedStrategy`, maintenir un dictionnaire `rowsByNiveau`:
```javascript
const rowsByNiveau = { bas: [], median: [], haut: [] };
// Chaque entrée : { y, height, niveauCode }
// Remplir au fur et à mesure des placements
```

### Constantes

```javascript
PLACEMENT_RULES.litDePose   // 40 mm
PLACEMENT_RULES.entraxe     // 30 mm
calculateCellSize(d)        // d + 30
```
