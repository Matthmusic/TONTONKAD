# Story 2.1 : Panel de variantes de placement

## Status

Done

---

## Story

**As a** électricien ou bureau d'études utilisant TontonKAD,
**I want** voir les configurations alternatives générées par le moteur de placement après chaque optimisation,
**so that** je puisse choisir la variante qui correspond le mieux à mes contraintes (encombrement, symétrie, accessibilité des réserves) plutôt que de n'avoir que le résultat unique imposé par l'algorithme.

---

## Acceptance Criteria

1. Après l'exécution de "Placer en grille" (`arrangeConduitGridNew`), si le moteur a généré ≥ 2 configurations valides, le `#layoutPreviewPanel` s'affiche automatiquement avec une card par variante.
2. Chaque card affiche : nom de la stratégie en français (cf. table de traduction), dimensions en mm (`width × height mm`), et score global en pourcentage (`(score * 100).toFixed(0) %`).
3. La première card (meilleure config, déjà appliquée) est marquée `active`.
4. Cliquer une card alternative : applique ce placement au canvas (positions des fourreaux converties avec la même formule Y-flip que `arrangeConduitGridNew`).
5. Après l'exécution de "Réduire au minimum" (`reduceToMinimumNew`), les variantes sont également exposées. En mode autoResize, chaque variante a ses propres dimensions — les appliquer au canvas ET aux inputs `boxWInput`/`boxHInput`.
6. Le panel se ferme via le bouton `#closeLayoutPreview` existant.
7. En mode OSNAP OFF ou si ≤ 1 config valide générée, le panel reste caché (comportement actuel inchangé).
8. `NappeLayout` expose un champ `strategyName` (chaîne, ex. `'familyLevelStrategy'`) rempli par chaque stratégie du `NappeGenerator`.
9. `computeBestPlacement()` expose les alternatives sur l'objet retourné : `best.alternatives = configs.slice(1)` (tableau de `NappeLayout`, trié par score desc, déjà scorés).
10. Zéro régression : les 114+ tests Jest passent.

  constructor(boxWidth, boxHeight, constraints = {}) {

**`renderVariantSVG(variant)`** (~ligne 2476, `script.js`) : génère un SVG miniature d'une variante. Attend :
- `variant.container = { width, height }` — dimensions en mm
- `variant.items = [{ id, diameter }]` — liste des fourreaux
- `variant.layout.placements = [{ id, x, y }]` — positions **centre** en mm, Y=0 en BAS

**Format des positions dans `buildNappeVariants`** :
- `NappeLayout.placedFourreaux[i].x/y` = coin **bas-gauche** de la cellule (Y=0 en bas)
- Centre = `x + cs/2`, `y + cs/2` (cs = taille de cellule)
- `renderVariantSVG` utilise `toY = y => (offY + (container.height - y) * scale)` — donc attend des centres avec Y=0 en bas ✓

### Coordonnées — Systèmes utilisés

| Système | Unité | Y=0 | Utilisé par |
|---------|-------|-----|-------------|
| NappeLayout | mm | Bas | `pf.x`, `pf.y` (coin cellule), `cfg.width/height` |
| Canvas pixels | px | Haut | `f.x`, `f.y`, `MM_TO_PX = 0.5` |
| SVG miniature | SVG units | Haut | `renderVariantSVG` (flip Y géré par `toY`) |

**Formule critique `applyNappeVariant`** (mode non-autoResize) :
```
x_canvas = (offsetX + pf.x + cs/2) × MM_TO_PX
y_canvas = (offsetY + cfg.height − pf.y − cs/2) × MM_TO_PX
```
avec `offsetX = (boxW - cfg.width) / 2`, `offsetY = (boxH - cfg.height) / 2`

### Noms des stratégies NappeGenerator

Grep `function familyLevelStrategy|function bottomLeftStrategy|...` dans `placement-engine.js` pour confirmer les noms exacts des méthodes. Les `strategyName` à assigner = nom exact de la méthode sans le suffixe `Strategy`.

### Stratégies selon `placementMode`

- `auto` → 7 stratégies (familyLevel, bottomLeft, centeredSymmetric, compactByDiameter, rectangularAspect, minWidth, minHeight)
- `rect43` → 3 stratégies (rectangularAspect, compactByDiameter, minHeight)
- `compact` → 3 stratégies (compactByDiameter, rectangularAspect, minHeight)

Le panel n'affiche les variantes que si ≥ 2 configs générées — en mode `compact` ou `rect43`, il peut y avoir 2-3 variantes (pas 7).
